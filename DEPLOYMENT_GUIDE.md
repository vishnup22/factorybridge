# Deployment guide

**Status:** nothing has been deployed. Every config below is written and checked locally. The cloud steps need
your accounts, billing decisions and approval. The exact remaining manual actions are at the end.

Target topology: **Vercel** (static SPA) → **Render** (FastAPI API + Celery worker, Postgres 16, Key Value/Redis on
the private network) → **Cloudflare R2** (private S3-compatible bucket for uploaded documents). The repo also stays
portable: the same images run under `docker compose`.

## 1. Local (reference environment)

Requirements: Docker Desktop, Python 3.12 with [`uv`](https://docs.astral.sh/uv/), Node 24.

```powershell
Copy-Item .env.example .env          # optional; defaults are safe local values
docker compose up -d --build --wait  # API http://127.0.0.1:8000, web http://127.0.0.1:5173
docker compose exec -T api python -m demo.seed
docker compose cp api:/srv/backend/var/demo_credentials.txt backend/var/demo_credentials.txt   # gitignored; don't share
uv --project backend run python scripts/demo_flow.py --base-url http://127.0.0.1:8000 --credentials backend/var/demo_credentials.txt
```

The `Makefile` has the same steps (`make up seed demo test e2e`) for shells with `make`. Postgres and Redis bind to
`127.0.0.1` only. The seed prints demo emails, never passwords.

## 2. Configuration contract

All configuration comes from environment variables (`backend/app/core/config.py`). With `ENVIRONMENT=production`,
the process **refuses to start** if any of these is true:

- `JWT_SECRET` is a dev default or shorter than 32 characters.
- `CORS_ALLOWED_ORIGINS` contains `*` or any non-`https://` origin.
- `DATABASE_URL` uses local or default credentials.
- `STORAGE_BACKEND` is not `s3`.
- `AI_PROVIDER=anthropic` is set without `ANTHROPIC_API_KEY` and `AI_MODEL`.
- The demo seed runs without `FB_DEMO_PASSWORD` (at least 16 characters).

Managed `postgres://` URLs are rewritten to the psycopg driver automatically. `TRUSTED_PROXY_HOPS=1` makes the
rate limiter use the client IP that Render's proxy appends, not one the client spoofed.

## 3. Object storage: Cloudflare R2

1. Create a bucket, e.g. `factorybridge-private`. Leave public access **off**.
2. Create an R2 API token with *Object Read & Write* scoped to that bucket.
3. Note the endpoint `https://<account-id>.r2.cloudflarestorage.com`, the access key and the secret.

Downloads use short-lived presigned URLs, so no bucket CORS rule is needed. CI exercises the S3 code path against
RustFS (an S3-compatible server). It has never run against R2.

## 4. Backend: Render Blueprint (`render.yaml`)

The Blueprint defines `factorybridge-api` (web, Docker), `factorybridge-worker` (Celery with embedded beat, exactly
one instance), `factorybridge-redis` (Key Value, `noeviction`, private only) and `factorybridge-db` (Postgres 16,
private only). Plans are left at Render defaults, so **review pricing before applying**.

1. Render Dashboard → *New → Blueprint* → connect `github.com/vishnup22/factorybridge` and select `render.yaml`.
2. Enter the `sync: false` secrets when prompted:
   - `CORS_ALLOWED_ORIGINS`: your Vercel URL, e.g. `https://factorybridge.vercel.app`. Set it on the API and the
     worker. You can deploy the frontend first to learn the URL, or use a placeholder `https://` origin and
     change it later.
   - `FB_DEMO_PASSWORD` (API only): at least 16 random characters. It seeds the synthetic demo accounts through
     `initialDeployHook`.
   - `OBJECT_STORAGE_ENDPOINT`, `OBJECT_STORAGE_BUCKET`, `OBJECT_STORAGE_ACCESS_KEY`, `OBJECT_STORAGE_SECRET_KEY`
     (API and worker), from step 3.
   - `ANTHROPIC_API_KEY` and `AI_MODEL`: leave empty for fixture mode.
3. `JWT_SECRET` and `HEALTH_TOKEN` are generated by Render in the shared env group and never committed.
4. Every deploy runs `alembic upgrade head` as a **pre-deploy command**. If it fails, the new version does not go
   live and the old one keeps serving.
5. Auto-deploy is **off** (`autoDeployTrigger: "off"`). Deploy manually from the dashboard after CI is green.

To switch on live AI later, set `ANTHROPIC_API_KEY` and `AI_MODEL` on both services, then change `AI_PROVIDER` to
`anthropic` in the env group. Spend is capped by `AI_DAILY_BUDGET_USD` (default 2.0).

## 5. Frontend: Vercel (`frontend/vercel.json`)

1. Vercel → *Add New Project* → import the repo, set **Root Directory = `frontend`** (framework preset Vite).
2. Set env var `VITE_API_BASE_URL=https://factorybridge-api.onrender.com` (your API URL). The build **fails** on
   Vercel if this is missing or not `https://`.
3. Deploy. `vercel.json` adds the SPA rewrite, HSTS, CSP, `X-Frame-Options: DENY`, and immutable caching for
   `/assets`.
4. If the API runs on a custom domain instead of `*.onrender.com`, add that domain to `connect-src` in the CSP in
   `frontend/vercel.json`.
5. Copy the deployed origin into Render's `CORS_ALLOWED_ORIGINS` (API and worker) and redeploy the API.

The Vercel CLI is not installed on this machine. The dashboard flow above doesn't need it.

## 6. Smoke test (run after every deploy)

```powershell
$env:HEALTH_TOKEN = "<value from Render env group>"
uv --project backend run python scripts/demo_flow.py --base-url https://factorybridge-api.onrender.com --smoke
```

This checks `/health/live` 200, `/health/ready` 200 (DB, Redis and storage must be ok; it also reports the migration revision and outbox backlog),
unauthenticated `/projects` 401, and HSTS over HTTPS. It is read-only. For a full end-to-end check, run without
`--smoke` and with `FB_DEMO_PASSWORD` set. That creates one new synthetic project. To run the UI flow against the
deployment, use `E2E_BASE_URL=https://<app>.vercel.app FB_DEMO_PASSWORD=... npx playwright test`.

## 7. Monitoring

- JSON logs with `correlation_id` on every line (Render log stream). Clients see the same ID in the
  `X-Correlation-ID` header and in error bodies.
- `/api/v1/metrics` (Prometheus text, needs `X-Health-Token`): request totals, a latency sum, unpublished outbox
  events, and job counts by status.
- Render health check on `/api/v1/health/live`. Point an external uptime check at `/health/ready` with the token.
- Not set up: Sentry or tracing, and alert routing. Both are listed as next work.

## 8. Rollback

- **App:** Render → service → *Rollback* to the previous deploy. Do this for the API and the worker together.
  Vercel → *Promote* the previous deployment.
- **Database:** migrations are forward-only in practice. **Don't run `alembic downgrade` blindly against
  production.** Approvals and audit rows are append-only, and a downgrade can drop data. If a migration is bad,
  roll the app back (old code tolerates added columns) and ship a corrective forward migration. Restore from a
  Render Postgres backup only as a last resort, and know that it loses writes made after the backup.
- **Config:** a broken env change causes a failed start, so Render keeps the previous instance serving. Fix the
  variable and redeploy.
